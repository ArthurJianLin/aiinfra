二、版本匹配矩阵（关键）

vLLM 跑不起来的根因是版本与硬件错配：不同 vllm 版本对 CUDA 与 torch 有硬性要求，而本机驱动被锁死在 CUDA 12.2。下表给出“该用什么”与“为什么不能用更新的”。

组件版本匹配矩阵
组件 推荐版本 本机驱动限制 说明
CUDA 运行时≤ 12.212.2驱动 535 仅支持到 CUDA 12.2，不能跑 13.x
torch2.5.1+cu121cu121/cu124cu126+ 需要 12.6+ 驱动，不可用
vllm0.7.3—0.8.x 强制 torch 2.6（需 12.4 驱动）；0.31.0 需 CUDA 13
transformers4.49.0—5.x 移除 tokenizer API，与 vllm 0.7.3 不兼容
模型Qwen2.5-0.5B—权重 0.5B 实测 GPU 占用约 0.93GB

为什么不能升级

vllm 0.31.0

面向 CUDA 13 编译，需要 libcudart.so.13；驱动 12.2 不提供也无法运行。不可用。

vllm 0.8.x

全系强制升级到 torch 2.6.0（默认 cu126），需要 CUDA 12.6+ 驱动，与 12.2 驱动冲突。不可用。

vllm 0.7.3

与 torch 2.5.1+cu121、CUDA 12.1 完全匹配，A10（Ampere）官方支持。当前选定版本。

硬性约束：GPU 驱动被锁定为 535（CUDA 12.2），这是不可绕过的天花板。因此所有 CUDA 12.2 以上、以及 torch 2.6+ 的版本都不可用。选型时必须先核对“vllm → torch → CUDA → 驱动”这一条链。

三、部署过程遇到的问题与解决

  1. 问题 1 · libcudart.so.13 找不到

    现象：导入 vllm 报 ImportError: libcudart.so.13: cannot open shared object file。
    根因：vllm 0.31.0 针对 CUDA 13 编译，需要 CUDA 13 运行时库；本机驱动仅 CUDA 12.2，无法提供。
    解决：降级 vllm 到兼容版本（0.7.3），驱动无需改动。

  2. 问题 2 · torch ABI 符号缺失

    现象：补上 CUDA 13 库路径后，报 undefined symbol: aoti_torch_memory_format_preserve_format。
    根因：vllm 0.31.0 需要更高版本的 torch，与已装 torch 2.5.1 的 ABI 不匹配。
    解决：与问题 1 一并由降级 vllm 解决。

  3. 问题 3 · vllm 0.8.x 需要 torch 2.6

    现象：尝试安装 0.8.x 时，依赖解析强制升级 torch 到 2.6.0（默认 cu126），需要 CUDA 12.6+ 驱动，与 12.2 驱动冲突。
    解决：回退选 vllm 0.7.3，其依赖与 torch 2.5.1+cu121 匹配，torch 保持不变。

  4. 问题 4 · transformers 5.x 不兼容

    现象：启动服务时 tokenizer 初始化报 Qwen2Tokenizer has no attribute all_special_tokens_extended。
    根因：环境中 transformers 5.17.0 移除了该 API，vllm 0.7.3 需要 4.x。
    解决：降级 transformers==4.49.0（vllm 0.7.3 官方配套版本）。

  5. 问题 5 · 模型权重缺失

    现象：模型缓存目录只有 tokenizer / config，没有 *.safetensors 权重文件，无法加载模型。
    解决：用 hf-mirror 补全下载权重。

  6. 问题 6 · 模型下载网络异常

    现象：直连 huggingface.co 报 Network is unreachable；走镜像后大文件下载报 xet 401 Unauthorized。
    根因：国内网络受限；新版 huggingface_hub 大文件走 xet 协议，镜像不代理。
    解决：设 HF_ENDPOINT=https://hf-mirror.com 且 HF_HUB_DISABLE_XET=1 强制经典下载。

  7. 问题 7 · 后台启动 source 不可用

    现象：后台脚本报 sh: 1: source: not found。
    根因：source 是 bash 内建，脚本用 sh 执行。
    解决：改用 POSIX 写法 . /home/ctyun/vllm-env/bin/activate。

四、LLM 启动方法

4.1 一次性启动（前台）

# 1) 进入虚拟环境
source ~/vllm-env/bin/activate

# 2) 设置镜像（下载模型时用）
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1

# 3) 启动服务（指定本地模型路径，前台运行）
vllm serve /home/ctyun/.cache/TeleAgent/huggingface/hub/models--Qwen--Qwen2.5-0.5B-Instruct/snapshots/7ae557604adf67be50417f59c2c2f167def9a775 \
  --host 127.0.0.1 \
  --port 8000 \
  --gpu-memory-utilization 0.5 \
  --max-model-len 4096

4.2 后台启动（nohup，可持续运行）

source ~/vllm-env/bin/activate
nohup vllm serve /home/ctyun/.cache/TeleAgent/huggingface/hub/models--Qwen--Qwen2.5-0.5B-Instruct/snapshots/7ae557604adf67be50417f59c2c2f167def9a775 \
  --host 127.0.0.1 --port 8000 --gpu-memory-utilization 0.5 --max-model-len 4096 \
  > vllm.log 2>&1 &

4.3 验证服务

# 查看可用模型
curl http://127.0.0.1:8000/v1/models

# 发起一次文本补全（model 用列表中的 id）
curl http://127.0.0.1:8000/v1/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"<模型id>","prompt":"你好","max_tokens":64}'
常用启动参数
参数 示例值 说明
--host / --port127.0.0.1 / 8000监听地址与端口
--gpu-memory-utilization0.5显存占用上限比例，过大可能 OOM
--max-model-len4096最大序列长度，决定 KV Cache 分配
--served-model-name可选自定义对外模型名，方便客户端调用
--dtypeauto权重精度，A10 下默认 bf16

建议：若需换更大的模型（如 Qwen2.5-7B），注意 --gpu-memory-utilization 与 --max-model-len 需相应调整，避免显存不足导致 OOM。
